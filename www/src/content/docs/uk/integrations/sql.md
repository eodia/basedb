У цьому сенс існування basedb: **ваші таблиці — справжні таблиці**. Будь-який клієнт
PostgreSQL читає їх за їхньою назвою.

## Назви

| Об’єкт | Фізична назва | Приклад |
|---|---|---|
| База | схема `b_<tenant>_<nom>` | `b_t4z56fq_ventes` |
| Середовище тестування | схема із суфіксом | `b_t4z56fq_ventes_recette` |
| Таблиця | її слагіфікована назва | `opportunites` |
| Поле | його слагіфікована назва | `echeance` |
| Зв’язок | `<table cible>_id` | `clients_id` |
| [SQL-подання](/basedb/uk/fonctionnalites/requetes-et-vues-sql/) | його технічна назва у схемі бази | `factures_a_encaisser` |

Сторінка **Документація API та MCP** кожної бази наводить їх усі, а `\d` у `psql` показує
описи (`COMMENT ON`).

## В інтерфейсі

**+** на панелі вкладок або меню **⋯** бази → **SQL-запит**: редактор із підсвічуванням
і автодоповненням, результат якого показується в тій самій сітці, що й ваші таблиці.

![Збережений запит і два SQL-подання серед таблиць](../../../../assets/screens/requete-sql.png)

- **Кожен читає тут зі своїми дозволами**: рівень «Керування» має доступ до всієї бази, зокрема
  на запис; інші учасники пишуть SQL лише для читання, де закритої таблиці не існує, а
  приховане поле зникає.
- Запит **зберігається** під таблицями — для себе, для всієї бази чи для груп — і, за
  бажанням, стає **SQL-поданням**: справжнім поданням PostgreSQL, розміщеним серед таблиць і
  доступним для читання з `psql`.

Усе докладно описано в [Запити та SQL-подання](/basedb/uk/fonctionnalites/requetes-et-vues-sql/).

## Через psql

З наданим `docker-compose.yml` PostgreSQL доступний на `127.0.0.1:5432`:

```bash
psql "postgres://basedb:<POSTGRES_PASSWORD>@localhost:5432/basedb"
```

```sql
SET search_path = b_t4z56fq_ventes;

SELECT o.nom, o.montant, c.nom AS client
FROM opportunites o
JOIN clients c ON c._id = o.clients_id
WHERE o.statut = 'gagne';
```

## Запис через SQL

Це дозволено. Обмеження (одиночний вибір, зв’язки, URL, обов’язковість) забезпечує
PostgreSQL, і вони відхиляють недійсне значення так само, як в інтерфейсі. А запис
**потрапляє в історію**: історія показує його як «Сеанс прямого SQL» разом із сеансом, що його
зробив, і його можна скасувати так само, як інші.

:::caution
Зміна **структури** через SQL (`ALTER TABLE`) оминає каталог basedb, який про неї не знатиме.
Використовуйте інтерфейс, API або пропозицію агента: рушій міграцій планує зміни, ставить
короткі блокування й підтримує каталог у точному стані.
:::
