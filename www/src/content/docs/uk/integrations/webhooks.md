Вебхук надсилає на адресу HTTPS **події** однієї чи кількох таблиць:
`record.created`, `record.updated`, `record.deleted`. Ними керують через **Вебхуки…** в меню
бази, у розділі **API та агенти**.

## Корисне навантаження

Тіло завжди є **масивом подій**, кожна з яких містить рядок **до** і **після** повністю, а
також список змінених полів:

```json
{ "events": [
  { "id": "0195e…", "type": "record.updated",
    "occurred_at": "2026-09-26T14:03:00.120Z",
    "tenant": "t4z56fq", "base": "b_t4z56fq_ventes", "table": "opportunites",
    "record_id": "0195a…",
    "actor": { "kind": "user" },
    "before": { "statut": "negociation", "montant": "125000", … },
    "after":  { "statut": "gagne", "montant": "125000", … },
    "changed": ["statut"] } ] }
```

Навіть запис, зроблений через прямий SQL, породжує свою подію: вони надходять з історії, яку
фіксує тригер.

## Підпис, порядок, повторні спроби

- **Підписано**: `X-Basedb-Signature: t=…,v1=…`, HMAC-SHA256 необробленого тіла, який слід
  перевірити перед десеріалізацією.
- **Упорядковано** за рядком: дві події одного рядка надходять по порядку.
- **Повторні спроби** в разі збою; після їх вичерпання вебхук вимикається, і його можна знову
  ввімкнути з інтерфейсу. Чергу й кожну доставку можна переглянути, повторити або скасувати.
- Доставка **щонайменше один раз**: усувайте дублікати за `X-Basedb-Delivery-Id` або
  `events[].id`.

## Адресати

Вебхуки надсилаються лише на **публічні адреси HTTPS**. Під час розробки
`BASEDB_WEBHOOK_DEV=1` дозволяє HTTP і локальні адреси.

Для **сервера вашої мережі** оператор екземпляра називає його в
`BASEDB_WEBHOOK_ALLOW` — ім’я, домен (`*.intra.example.com`), адреса або діапазон
(`10.12.0.0/16`):

```bash
BASEDB_WEBHOOK_ALLOW=chat.intra.example.com,10.12.0.0/16
```

Ці цілі приймаються незалежно від їхньої адреси, порту та схеми, включно з HTTP.
Список також діє для HTTP-запитів автоматизацій і джерел синхронізованих таблиць; він
налаштовується в середовищі, а не в інтерфейсі.

## Без вебхука: стежити за таблицею

Сервер, з яким не можна зв’язатися, теж може **підключитися** до basedb і стежити за
таблицею через потік у реальному часі, маючи токен інтеграції бази:

```bash
curl -N "https://basedb.example.com/api/v1/t4z56fq/events?base=b_t4z56fq_ventes&table=opportunites" \
  -H "Authorization: Bearer $BASEDB_TOKEN"
```

Потік (`text/event-stream`) передає **сигнали** — подію `records` з ідентифікаторами
рядків, які створено, змінено чи видалено, — але ніколи самі значення: програма потім
перечитує ці рядки через [REST API](/basedb/uk/integrations/api-rest/). Відкликаний токен
закриває свій потік протягом 20 секунд. Для таблиці, яку читають рідко, достатньо
періодично перечитувати змінені рядки: `filter=_updated_at gt "2026-09-30T08:00:00Z"`.
