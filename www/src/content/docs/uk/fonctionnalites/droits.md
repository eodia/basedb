Дозволи надаються **групам**, ніколи — окремим людям поодинці. Рівень, заданий для проєкту,
бази чи таблиці, поширюється на все, що під ними, зокрема на те, що буде створено пізніше.

## Чотири рівні

| Рівень | Дає змогу |
|---|---|
| **Немає доступу** | нічого: ресурс невидимий |
| **Читання** | бачити рядки, коментувати їх, створювати собі особисті подання, переглядати структуру та інформаційні панелі, ставити власні запитання, писати SQL лише для читання й зберігати свої особисті запити |
| **Редагування** | а також створювати, змінювати й видаляти рядки |
| **Керування** | а також змінювати структуру, створювати спільні подання, інформаційні панелі та збережені запитання, публікувати інформаційну панель за посиланням, ділитися запитами, створювати SQL-подання, автоматизації, інтеграції та токени; його SQL має доступ до всієї бази, зокрема на запис |

Дозволи **підсумовуються**: людина отримує найвищий рівень, який їй надає будь-яка з її груп.
Якщо дати таблиці менше, ніж її базі, таблиця стає «гранулярною».

Дві групи існують завжди: **Адміністратори**, які керують усім, і **Усі користувачі**, до якої
належить кожен обліковий запис, — те, що надано їй, мають усі.

## Аж до поля

Під сіткою рівнів розділ **Поля** приховує стовпець від групи або робить його недоступним для
змін. Екран також показує, що саме бачить конкретна людина і завдяки якій групі.

Приховане поле відсутнє всюди: у сітці, поданнях, API, MCP, історії, SQL, написаному в
інтерфейсі, та в SQL-поданнях. Фільтрування чи сортування за ним дає такий самий результат, як
для поля, якого не існує.

## А як щодо SQL?

В інтерфейсі SQL підпорядковується тим самим дозволам, які застосовує сам PostgreSQL: без рівня
«Керування» запит виконується лише для читання, від імені ролі, власної для кожної людини, де
закритої таблиці не існує, а приховане поле відхиляється. [SQL-подання](/basedb/uk/fonctionnalites/requetes-et-vues-sql/)
читається з дозволами того, хто його читає, а поширення запиту поширює лише його текст.

А от **прямий доступ через `psql`** до бази basedb не контролює: він читає все, зокрема
приховані поля. Обмеження захищають поверхні продукту — інтерфейс, API, MCP, — але ніколи не
захищають від того, хто має SQL-доступ до бази; такий доступ налаштовується через `GRANT`
PostgreSQL, які задає оператор.

## Облікові записи та вхід

- Обліковий запис створюється з **тимчасовим паролем**, який показується один раз і який
  потрібно змінити під час першого входу.
- Вхід виконується за паролем або через постачальника **OpenID Connect**, якого налаштував
  оператор.
- Дії адміністрування потребують **привілейованого сеансу**: пароль, повторно введений протягом
  останніх п’яти хвилин.
- Сеанси можна відкликати; відкликання сеансу одразу робить недійсними його токени доступу.

## Ваші налаштування

**Налаштування** в меню профілю внизу ліворуч стосуються лише вас:

| Вкладка | Що там можна зробити |
|---|---|
| **Профіль** | показуване ім’я; адреса для входу; постачальники ідентифікації, пов’язані з обліковим записом, — пов’язати чи відв’язати |
| **Безпека** | змінити пароль; відкриті сеанси — закрити їх по одному або всі разом |
| **Зовнішній вигляд** | мова інтерфейсу; тема; порядок дати — `25/09/2026` або `2026-09-25` — і перший день тижня в календарях |
| **Сповіщення** | види сповіщень, які ви більше не хочете отримувати |
| **Токени** | створені вами токени інтеграції в усіх ваших базах, їхнє останнє використання та відкликання |

basedb розмовляє **двадцятьма мовами**: французькою, англійською, німецькою, іспанською,
італійською, португальською (Бразилія), нідерландською, польською, чеською, шведською,
данською, норвезькою, фінською, румунською, угорською, турецькою, українською, японською,
китайською спрощеною та корейською. Типово інтерфейс бере мову вашого браузера; **Мова** у
вкладці **Зовнішній вигляд** дає змогу задати іншу. Числа й дати відповідають вибраній мові.

Тема зберігається лише в браузері; мова, порядок дати й перший день тижня супроводжують вас з
одного комп’ютера на інший. Зміна адреси або прив’язування постачальника потребує
привілейованого сеансу; обліковий запис без пароля, який входить через постачальника, зберігає
адресу цього постачальника.

## Єдина точка застосування

Усі поверхні — інтерфейс, API, MCP, опубліковані форми й подання, автоматизації — проходять
через ту саму точку прийняття рішень щодо дозволів у ядрі. Приватного маршруту для інтерфейсу
не існує: якщо екран чогось не показує, це тому, що API цього не повернув.

Працює й навпаки: екран **не пропонує того, що буде відхилено**. Без рівня «Керування» екран
«Структура» доступний без кнопок і олівця, а імпорт не пропонує створити таблицю; без права
створювати чи видаляти рядки сітка не пропонує ні рядка для додавання, ні «Видалити».
