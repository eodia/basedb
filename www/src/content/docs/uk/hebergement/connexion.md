## Перший вхід

На новому екземплярі перша сторінка створює **обліковий запис адміністратора**: ваше ім’я,
ваша адреса, пароль на ваш вибір. Створіть його до того, як екземпляр стане доступним для
інших, — на домені або з портом, відкритим на всіх інтерфейсах.

## Створення облікових записів

Типово будь-хто, хто може відкрити екземпляр, може **створити обліковий запис**, а потім —
власні проєкти. Нічого іншого така людина не бачить: проєкти інших людей стають їй доступними
через **запрошення**.

У **Адміністрування → Користувачі** картка «Створення облікових записів»:

- закриває створення облікових записів: тоді створити його можуть лише запрошені люди;
- або обмежує його певними доменами — `exemple.fr, autre.fr` допускає лише такі адреси.

## Запрошення до проєкту чи бази

Той, хто має рівень **Керування** для проєкту чи бази, може ними поділитися: меню проєкту (або
бази) → **Поділитися…**, адреса, рівень — «Читання», «Редагування» або «Керування». basedb
створює **посилання-запрошення**, дійсне 7 днів, яке ви надсилаєте людині у будь-який зручний
спосіб: відкривши його, вона входить або створює обліковий запис. Той самий екран показує, хто
має доступ, дає змогу змінити рівень чи відкликати доступ і зберігає посилання, що очікують,
щоб надіслати їх повторно.

Той, хто керує, ніколи не надає більше, ніж те, чим керує сам: той, хто керує базою, може
поділитися базою, але не її проєктом.

## Вхід через Google, Microsoft…

basedb підтримує **OpenID Connect**: Google, Microsoft Entra ID, GitLab, Keycloak, Authentik,
Okta… Кожен налаштований постачальник додає кнопку «Продовжити з …» на екрани входу, створення
облікового запису та запрошення.

1. Задайте публічну адресу basedb у `.env`:

   ```bash
   BASEDB_PUBLIC_URL=https://basedb.example.com
   ```

2. У постачальника створіть вебзастосунок; його **адреса повернення** —
   `https://basedb.example.com/auth/oidc/<nom>/callback`, де `<nom>` — назва, яку ви даєте йому
   нижче (`google`, `microsoft`…).

3. Оголосіть його в `.env`:

   ```bash
   BASEDB_OIDC_PROVIDERS=google,microsoft

   BASEDB_OIDC_GOOGLE_CLIENT_ID=…
   BASEDB_OIDC_GOOGLE_CLIENT_SECRET=…

   BASEDB_OIDC_MICROSOFT_ISSUER=https://login.microsoftonline.com/<id-organisation>/v2.0
   BASEDB_OIDC_MICROSOFT_CLIENT_ID=…
   BASEDB_OIDC_MICROSOFT_CLIENT_SECRET=…
   ```

4. `docker compose up -d`: під час запуску basedb виводить перелік прийнятих постачальників і
   повідомляє, чого бракує тим, яких він пропустив.

| Змінна для постачальника `<NOM>` | Призначення |
|---|---|
| `BASEDB_OIDC_<NOM>_CLIENT_ID`, `_CLIENT_SECRET` | застосунок, зареєстрований у постачальника |
| `BASEDB_OIDC_<NOM>_ISSUER` | видавець; не потрібен для `google` і `gitlab` |
| `BASEDB_OIDC_<NOM>_LABEL` | назва на кнопці — типово `Google`, `Microsoft` |
| `BASEDB_OIDC_<NOM>_SCOPES` | типово `openid email profile` |
| `BASEDB_OIDC_<NOM>_SIGNUP` | `off`: допускає лише наявні облікові записи |

**Перший вхід створює обліковий запис** настільки, наскільки це дозволяють налаштування
створення облікових записів: якщо воно відкрите — запис створюється; якщо обмежене доменами —
лише для їхніх адрес. Адреса, яка вже належить обліковому запису з паролем, ніколи не
переймається: її власниця входить зі своїм паролем. Секрети лишаються в середовищі: у базу з
них нічого не записується.

:::note
GitHub не є постачальником OpenID Connect: тут його використати не можна.
:::
