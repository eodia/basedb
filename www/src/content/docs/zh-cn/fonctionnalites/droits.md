权限授予**用户组**，从不逐个授予个人。在项目、数据库或数据表上设置的级别会向下传递到其下的所有内容，包括以后创建的内容。

## 四个级别

| 级别 | 允许 |
|---|---|
| **无访问权限** | 什么都不能做：资源不可见 |
| **可查看** | 查看行、发表评论、创建个人视图、查看结构和仪表盘、提出自己的问题、编写只读 SQL 并保存个人查询 |
| **可编辑** | 以上权限，外加创建、修改、删除行 |
| **可管理** | 以上权限，外加修改结构，创建共享视图、仪表盘和已保存的问题，通过链接共享仪表盘，共享查询，创建 SQL 视图、自动化、集成和令牌；其 SQL 可访问整个数据库，包括写入 |

权限可以**叠加**：一个人会获得其所属用户组中给予的最高级别。给某张数据表的权限低于其所在数据库时，该数据表就成为“细粒度”的。

有两个用户组始终存在：**管理员**，负责管理一切；以及**所有用户**，每个账户都属于该组——授予它的权限，所有人都拥有。

## 细化到字段

在级别网格下方，**字段**可以对某个用户组隐藏一列，或将其设为不可修改。该界面还会显示某个具体的人实际能看到什么，以及是通过哪个用户组获得的。

隐藏的字段在任何地方都不存在：网格、视图、API、MCP、历史记录、界面中编写的 SQL 以及 SQL 视图中都没有它。对它进行筛选或排序时，响应与字段不存在时相同。

## 那 SQL 呢？

在界面中，SQL 遵循相同的权限，并由 PostgreSQL 本身执行：没有可管理级别时，查询在专属于该用户的角色上以只读方式执行，对其不开放的数据表并不存在，隐藏的字段会被拒绝。[SQL 视图](/basedb/zh-cn/fonctionnalites/requetes-et-vues-sql/)按读者的权限读取，共享查询只会共享其文本。

而对数据库的**直接 `psql` 访问**则不受 basedb 管控：它可以读取一切，包括隐藏字段。这些限制保护的是产品的各个入口——界面、API、MCP——而无法防范拥有数据库 SQL 访问权限的人；这类访问应由运维人员通过 PostgreSQL 的 `GRANT` 来控制。

## 账户与登录

- 账户创建时带有一个**临时密码**，只显示一次，首次登录时必须更改。
- 可以使用密码登录，或通过运维人员配置的 **OpenID Connect** 身份提供商登录。
- 管理操作需要**高权限会话**：即在最近五分钟内重新输入过密码。
- 会话可以被撤销；撤销会话会立即使其访问令牌失效。

## 您的设置

左下角个人资料菜单中的**设置**只与您自己有关：

| 标签页 | 可以做什么 |
|---|---|
| **个人资料** | 显示的姓名；登录邮箱地址；与账户关联的身份提供商，可关联或解除关联 |
| **安全** | 修改密码；已打开的会话，可逐个或全部关闭 |
| **外观** | 界面语言；主题；日期顺序——`25/09/2026` 或 `2026-09-25`——以及日历中每周的第一天 |
| **通知** | 您不想再接收的通知类型 |
| **令牌** | 您在所有数据库上创建的集成令牌、它们最近一次的使用情况，以及撤销操作 |

basedb 支持**二十种语言**：法语、英语、德语、西班牙语、意大利语、葡萄牙语（巴西）、荷兰语、波兰语、捷克语、瑞典语、丹麦语、挪威语、芬兰语、罗马尼亚语、匈牙利语、土耳其语、乌克兰语、日语、简体中文和韩语。默认情况下，界面使用浏览器的语言；**外观**中的**语言**可以指定其他语言。数字和日期会跟随所选语言。

主题只对当前浏览器生效；语言、日期顺序和每周第一天则会随您的账户在不同设备间保持一致。更改邮箱地址或关联身份提供商需要高权限会话；没有密码、通过身份提供商登录的账户，会沿用该提供商的邮箱地址。

## 唯一的执行点

所有入口——界面、API、MCP、共享表单和共享视图、自动化——都经过内核中同一个权限决策点。界面没有私有路由：界面上没有显示的内容，就是 API 没有返回的内容。

反之亦然：界面**不会提供会被拒绝的操作**。没有可管理级别时，结构界面只能查看，没有按钮和铅笔图标，导入也不会提供创建数据表的选项；没有创建或删除行的权限时，网格既不提供新增行，也不提供“删除”。
