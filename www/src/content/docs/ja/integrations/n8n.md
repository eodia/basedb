**n8n-nodes-basedb**パッケージは、n8nに3つのノードを追加します：

| ノード | 役割 |
|---|---|
| **basedb** | テーブルの行を読み書きし、行にコメントします。n8nのAIエージェントからツールとしても使えます |
| **basedb Trigger** | 直前の確認以降に作成された行——または作成または変更された行——ごとにワークフローを起動します |
| **basedb Webhook Trigger** | 行が作成、変更、削除された瞬間にワークフローを起動します |

## インストール

n8nで：**Settings › Community Nodes › Install**、続けて`n8n-nodes-basedb`。

インターフェースなし——キュー方式、あらかじめ組み込んだDockerイメージ——の場合：`~/.n8n/nodes`フォルダーで`npm install n8n-nodes-basedb`を実行し、n8nを再起動してください。

## 認証情報

n8nで**basedb API**の認証情報を作成します：

| フィールド | 値 |
|---|---|
| **Instance URL** | basedbを開くアドレス：`https://basedb.exemple.fr` |
| **Workspace** | ワークスペースの識別子。APIのアドレスに使われるもの（`/api/v1/<espace>/…`）：`t4z56fq`——インスタンスが`BASEDB_TENANT`を設定していない限り |
| **Token** | **連携トークン**：データベースの **⋯** メニュー → **APIとエージェント** → **APIとMCPのトークン…** |

トークンは**1つの**データベースを開きます。その行を読み取り、書き込み用に作成されていれば書き込みますが、作成した人を超える権限を持つことはなく、**決して削除しません**。保存時、n8nは接続を試み、トークンが拒否された場合はその旨を伝えます。

## 読み書き：basedbノード

| 操作 | 内容 |
|---|---|
| **Row › Create** | 行を追加します |
| **Row › Create or Update** | 選んだフィールドがその値を持つ行を変更するか、なければ追加します |
| **Row › Get** | `_id`で行を1件読み取ります |
| **Row › Get Many** | フィルターに合う行を、指定した順序で、上限まで、またはすべてをページ単位で読み取ります |
| **Row › Update** | `_id`または他のフィールドで見つけた行を変更します |
| **Comment › Create** | 行にコメントします。@メンションはその人に通知します |

**データベース**と**テーブル**は、トークンが開くものの一覧から選びます。書き込むフィールドは、basedbでの名前で表示され、単一選択はその選択肢とともに、メンバーフィールドはワークスペースのメンバーとともに表示されます。計算フィールド——数式、ルックアップ、ロールアップ、自動採番——は、basedb自身が書き込むため表示されません。フィールドが拒否する値は、basedbのコードとその意味とともにノードを停止させます。

- **フィルター**と**並べ替え**は、フィールドのSQL上の技術名を使います：`statut eq "gagne" and montant gte 10000`、`-montant,nom`。文法は[REST API](/basedb/ja/integrations/api-rest/#読み取り)と同じです。
- **数値**は小数点付きのテキストで届きます（`"1250.50"`）。数字を1つも失わないためです。**Numbers as Numbers**オプションで数値に変換できます。
- **リレーション**は`{ "id": …, "display": … }`として読み取られ、リンクされた行の`_id`で書き込まれます。
- **Create or Update**は、複数の行を変更することは決してありません：複数の行がその値を持つ場合、ノードは推測せずに停止します。
- **Delete**操作はありません：トークンは削除しません。行を取り除くには、印を付けるか（「Archivé」のようなステータス）、削除を[オートメーション](/basedb/ja/fonctionnalites/automatisations/)に任せてください。

## ワークフローを起動する

### 定期確認ごとに：basedb Trigger

このノードは、選んだ間隔（毎分、毎時…）でbasedbに、前回以降に**作成された**——または**作成または変更された**——行を尋ねます。必要ならフィルターも追加できます。basedbがn8nに到達できないときでも動作します。最初の確認では、テーブルの現在位置を記録するだけで、何も出力しません。エディターからの試行では、後続のノードをつなげられるように最後の行を返します。

### その瞬間に：basedb Webhook Trigger

行が作成、変更、削除されるたび——直接PostgreSQLに書かれたSQLによる場合も含めて——、ワークフローがすぐに起動します：

1. ノードを追加し、その**Production URL**をコピーします。
2. basedbで、データベースの **⋯** メニュー → **APIとエージェント** → **Webhook…**：このアドレス宛てのWebhookを作成し、対象のテーブルとイベントを選びます。
3. basedbは**署名シークレット**を一度だけ表示します：n8nの**basedb Webhook**認証情報に設定してください。
4. ワークフローを有効化します。

各イベントは1つの要素になります：その`type`（`record.created`、`record.updated`、`record.deleted`）、テーブル、行の**変更前**と**変更後**、そして変更されたフィールド（`changed`）。ノードは各配信の**署名**を検証し、署名がない、誤っている、または5分より古いものには`401`を返します。basedbは**少なくとも1回**届けます：ワークフローが同じイベントを2回処理してはならない場合は、イベントの`id`で重複を除いてください。

:::note
basedbは**公開HTTPS**のアドレスにしかWebhookを送りません：プライベートネットワーク上のn8nには、代わりに**basedb Trigger**を使ってください。[Webhook](/basedb/ja/integrations/webhooks/)をご覧ください。
:::

## ノードを使わない場合

n8nの**HTTP Request**ノードもbasedbと話せます：`Authorization: Bearer <jeton>`ヘッダー、往復ともJSON、`after`に渡す`meta.next_cursor`によるページング（`{{ $response.body.meta.next_cursor }}`）、そして障害後の再開は`_updated_at`によるフィルターと`…/<table>/deleted?since=`で行います。
